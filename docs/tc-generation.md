# TC 자동 생성

프로젝트 메뉴의 **TC 생성**에서 쓴다. 방식은 둘이다.

| 방식 | 입력 | 하는 일 | LLM |
| --- | --- | --- | --- |
| 요구사항 기반 | 요구사항·SR 명세 (한 줄에 하나) | 정규화 → 조건·경계 추출 → 정상·예외·경계 TC 생성 → 검증·매핑 | 조건 추출·TC 문장 |
| 상품 패턴 | 수신 화면 분기 · 여신 부결 룰 패턴 | 분기·선택지·범위·부결 사유별 케이스 전개 | 쓰지 않는다 (명세에서 패턴을 뽑을 때만) |

## 역할 나눔 — 모델은 읽고 쓰기만, 판정은 코드

모델은 "조건 읽어 내기"와 "케이스 문장 쓰기"만 한다. 아래는 전부 코드(`server/src/studio/domain/tc-generation.ts`)가 정한다.

- **정규화**: NFKC, 글머리표·공백 정리, 중복 문장 제거, 자주 틀리는 맞춤법 몇 개(되요→돼요 등). 고친 내역을 결과에 남긴다. `SR-1234`·`REQ-1` 같은 번호는 그대로 쓰고, 없으면 `REQ-001`부터 붙인다. `#` 줄은 구분 제목이다.
- **민감정보**: 주민·외국인등록번호, 카드번호(Luhn 확인), 휴대전화, 계좌, 이메일, 여권, 운전면허를 `[계좌번호]`처럼 바꾼 뒤에만 모델에 보낸다. **원문은 저장하지 않는다.**
- **지시문 차단**: "이전 지시를 무시" 같은 줄은 모델에 보내기 전에 빼고 무엇을 뺐는지 남긴다. 프롬프트에도 입력은 데이터라고 적지만, 그것만 믿지 않는다.
- **경계값**: `N 이상/이하/초과/미만`, `최소/최대 N`, `N~M`, 시각 범위 `23:30부터 00:30까지`를 코드가 읽어 해당·미해당 값을 계산한다(소수 자릿수·자정 넘김 처리). 모델이 그 값의 케이스를 빠뜨리면 코드가 채운다. 기대결과는 "조건에 해당할 때의 처리"처럼 중립으로 쓴다. `5회 이상이면 잠금`처럼 이상이 거절인 규칙도 있기 때문이다.
- **검증**: 모델이 댄 근거 구절이 원문에 있는지(`원문 확인`/`원문 없음`), 없는 요구사항 번호, 입력값까지 같은 중복(남는 쪽이 요구사항 매핑을 이어받는다), TC 없는 조건·요구사항, 예외·경계 없는 조건을 표시한다.
- **기대결과**: 요구사항에 적히지 않은 결과는 지어내지 말고 `요구사항에 명시 없음 — 확인 필요`로 쓰게 한다. 그런 TC가 나오면 명세에 빈칸이 있다는 뜻이다.

## 상품 패턴

```json
{ "domain": "loan", "name": "…", "fields": [{ "key": "score", "label": "신용점수", "type": "number", "unit": "점", "sample": "780" }],
  "branches": [], "rules": [{ "code": "R01", "reason": "신용점수 기준 미달", "field": "score", "op": "<", "value": "600" }] }
```

- `fields`: 입력 항목. 숫자는 `min`·`max`·`step`, 선택형은 `options`. `sample`은 모든 룰을 통과하는 표본값이다.
- `branches`: **선택형 항목의 선택지 하나**에 붙는 화면 분기. 숫자 조건은 분기가 아니라 부결 룰이다.
- `rules`: `값 op 기준`이 참이면 부결.
- 전개: 기준 고객 1건, 선택지별, 범위 최소·최대 안팎, 분기별, 부결 룰마다 "그 룰 하나만 위반(부결)"과 "기준 바로 안쪽(통과)", 복수 사유 1건.
- 기본 예시 두 개(가상 자유적금·가상 직장인 신용대출)는 코드 상수라 수정할 수 없다. 복제해서 등록한다.
- **명세에서 패턴 추출**은 모델이 초안을 만들고 코드가 고친다. 원문에 없는 범위(신용점수 0~1000 같은)는 지운다. 2억원·5천만원처럼 단위가 붙은 숫자도 원문 대조를 한다. 부결 룰과 겹치는 범위도 지운다(같은 값에 '입력 오류'와 '부결'이 함께 붙으므로). 선택지가 아닌 분기도 뺀다. 지운 내역을 보여 주고, 사람이 확인해 저장하면 패턴 라이브러리에 등록된다.

## 저장 (비기능)

| 요구 | 구현 |
| --- | --- |
| 저장 암호화 | 본문 AES-256-GCM. 키는 `HEIMDALL_TC_KEY`(64자 hex) 또는 데이터 디렉터리의 `tc-data.key`(0600, 처음 쓸 때 생성). **키를 잃으면 기존 기록을 못 연다.** |
| 무결성 | 결과의 SHA-256을 같이 저장하고 열 때마다 다시 계산해 `무결성 확인/불일치`를 표시 |
| 접속기록 | 생성·열람·내보내기·삭제를 `heimdall_tc_access`에 사용자·시각과 함께 남긴다(삭제 뒤에도 남음) |
| 보관기간 | `HEIMDALL_TC_RETENTION_DAYS`(기본 365일). 목록을 열 때 지난 기록을 지운다 |
| 설명가능성 | 조건마다 원문 근거 구절, TC마다 근거·출처(AI/코드 규칙/상품 패턴), 단계별 호출 시간·입력 크기·산출 수 |
| 접근통제 | 로그인 필수, 프로젝트 범위 확인 |

## 남은 것

- 엑셀 요구의 "LLM 외부 전송 금지·내부망 처리"는 지키지 못한다. 지금은 설정된 OpenRouter(기본 deepseek-v4.1-flash)로 보내고, 마스킹이 그 대신이다. 내부망 모델은 AI 모델 관리의 OpenAI 호환 주소로 바꾸면 된다(코드 변경 없음).
- 생성한 TC를 시나리오(실행)로 넘기는 연결은 없다. 범위를 생성까지로 정했다(엑셀 1.1.2는 26년 범위 제외 가능).
- 형태소 수준의 오탈자 교정은 하지 않는다.
