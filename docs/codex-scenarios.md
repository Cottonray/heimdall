# Codex 테스트 시나리오

AI 시나리오 실행은 실제 Codex CLI 0.146.0의 독립 대화로 처리한다. 한 실행의 반복 단계는 같은 thread를 resume한다. 실행이 끝나면 임시 HOME과 프로세스를 정리한다. 이어서 실행하면 저장된 해당 시나리오의 목표·관찰·최근 기록을 새 독립 대화에 제공한다.

## 권한 경계

- 모델은 파일·셸·브라우저·MCP·배포 도구를 받지 않는다. Codex의 Responses 요청을 전용 loopback 게이트웨이가 AI 설정의 Chat Completions 연결로 변환한다. upstream 요청에는 도구 정의가 없으며 tool_calls 응답을 거부한다. 응답은 assistant 텍스트 이벤트로만 Codex에 돌려준다. 따라서 프롬프트에만 의존한 권한 제한이 아니다.
- 실제 AI 키는 게이트웨이의 서버 메모리에만 존재한다. Codex에는 실행마다 발급하는 loopback 전용 임시 토큰과 비어 있는 임시 HOME을 전달한다. 사용자 Codex 설정·MCP·hooks를 가져오지 않는다. 첫 실행은 read-only sandbox다.
- 결과 JSON은 기존 validateAction과 URL 정책을 통과한 뒤 선택된 세션의 테스트 실행기로 처리한다. 임의 생성 코드를 eval하거나 셸에서 실행하지 않는다. 시나리오마다 `runs/studio/<UUID>/scenario.spec.ts` 또는 `scenario.appium.ts`만 서버 생성기가 갱신한다.
- 실행당 최대 12단계, Codex 응답당 최대 90초. 실제 검증 동작 성공 없이 통과로 판정하지 않는다. 사람 개입·종료 이후 도착한 결과는 epoch 검사로 실행하지 않는다.

## 코드 보기

Playwright/Appium TypeScript는 동일한 생성기를 화면·내보내기·시나리오 파일에 사용한다. 세션 동작 갱신에 맞춰 코드가 갱신된다. 실행 기록·디버깅 탭은 제거하고 API 도구는 유지한다. Android 내보내기도 동작 JSON 대신 Appium 코드다.

## 운영

실행 파일 기본 경로는 `/opt/aiqa/server/codex/bin/codex`이며 `AIQA_CODEX_BIN`으로 지정할 수 있다. npm 공식 `@openai/codex@0.146.0-linux-x64` 배포물의 SHA-512 integrity 검증 후 vendor 디렉터리를 server/codex에 설치한다. 바이너리는 Git에 커밋하지 않는다. 서버 소스 배포 후 서비스 재시작이 필요하다.

검증: 실제 로컬 Codex CLI와 mock 제공자로 thread resume 2회, 제공자 인증 헤더 전달, upstream 도구 정의 미전달을 확인했다. 전체 검사와 Appium 코드/문자열 이스케이프·API 내보내기 회귀 검사를 수행한다.

## 프로젝트 소스 참고 (2026-10-12)

프로젝트 설정의 표에서 최대 5개의 Git/SVN HTTPS 저장소를 등록하고 각 저장소의 설명을 따로 저장한다. 프로젝트 설명과 저장소별 설명·주소·revision·소스 발췌를 함께 AI에 전달한다. 기존 단일 저장소 설정도 읽으며 다음 저장 시 배열로 전환한다. aiqa_projects.source JSONB는 자동 추가하며 기존 프로젝트는 빈 설정을 유지한다. Codex 실행 시작 때 현재 프로젝트 소스를 임시 디렉터리로 읽고 revision과 최대 40개 파일·파일당 8,000자·총 80,000자의 발췌를 AI 설정의 모델에 전달한다. 참고 자료는 지시가 아닌 비신뢰 데이터이며 UI 관찰과 기존 동작 검증은 그대로 적용한다. 원본 저장소를 변경하거나 실행하지 않는다. Git은 체크아웃·서브모듈 없이 읽고 SVN은 list/cat만 실행한다. 임시 자료는 성공·실패 후 삭제한다. 조회 실패 시 테스트를 일시 정지하고 오류를 표시한다.

서버에 git/subversion이 필요하다. 기본 허용 호스트는 github.com,gitlab.com,svn.apache.org이며 사내 저장소는 운영자가 AIQA_SOURCE_HOSTS에 명시한다. 사용자 주소에 인증정보·쿼리·비표준 포트를 허용하지 않는다. 현재는 익명 HTTPS 접근만 지원하며 비공개 저장소 인증 연결은 별도 구현이 필요하다. 기존 사용자 HOME·Git 인증 설정은 읽지 않는다. 민감 파일명·빌드 산출물은 제외하지만 소스 자체에 비밀값이 들어 있지 않은 저장소만 연결해야 한다. 저장소당 최대 조회 시간은 60초이고 전체 소스 분석을 보장하지 않는다.

## 대화형 터미널 (2026-10-12)

하단 폼을 xterm.js + node-pty 기반 실제 Codex TUI로 교체한다. 터미널 프로세스는 별도 aiqa-terminal 컨테이너에서 --dangerously-bypass-approvals-and-sandbox로 실행한다. 운영 DB·키·사용자 HOME·Docker 소켓을 마운트하지 않는다. 컨테이너는 읽기 전용 루트, 임시 작업 디렉터리, 권한 제거, 프로세스·메모리 제한을 사용한다. master와 terminal 전용 내부 네트워크만 연결한다.

모델은 AI 설정을 사용하며 키는 master에만 남는다. gateway가 qa_observe/qa_action만 제공하고 선택된 테스트 세션의 기존 검증기를 거친다. 터미널의 일반 셸·파일 도구는 모델에 전달하지 않는다. 종료된 테스트에서는 코드 상담만 가능하고 실제 조작은 재실행이 필요하다. 저장소별 설명과 소스 발췌를 초기 문맥으로 제공한다. 연결 해제·인증 만료 시 터미널을 종료하고 임시 HOME을 제거한다. 동시에 최대 4개, 테스트마다 하나, 연결당 최대 30분이다.

운영 준비: server 의 Yarn 의존성(node-pty 포함)을 terminal-runtime/node_modules에 Linux용으로 설치하고 runs/.terminal-key를 32바이트 이상의 임의 비밀값으로 준비한다. compose의 aiqa-terminal은 전용 네트워크와 해당 키 파일만 공유한다. 변경 시 타입·린트·테스트 검증 절차는 2026-10-12 사용자 지시로 생략하며 화면 빌드와 배포 명령 결과만 확인한다.

## 재실행과 모델 고정 (2026-10-13)

재실행은 기존 탭의 React key를 유지하며 Codex WebSocket·PTY·대화·스크롤을 재생성하지 않는다. 서버는 같은 프로젝트에서 현재 실행을 parent로 갖는 새 실행만 조작 대상으로 전환한다. 각 AI 요청은 시작 당시 실행에 묶이며 전환 전에 시작한 응답은 새 기기를 조작하지 못한다. 다음 요청에는 새 실행 상태를 제공한다.

Codex의 model_catalog_json에 AI 설정 모델 한 개와 텍스트 게이트웨이 기능을 등록한다. 32,000 토큰은 제공자 최대 성능을 뜻하지 않는 게이트웨이 문맥 한도다. 다른 모델 요청은 서버에서 거부하며 실제 추론은 계속 AI 설정의 모델을 사용한다. 타입·린트·테스트는 사용자 지시대로 생략하고 화면 배포 빌드만 수행한다.

Codex HOME은 전용 컨테이너의 /home/codex tmpfs에 생성한다. /tmp 아래 helper binary 생성 거부 경고를 피하며 연결 종료 시 제거한다.

배포: 2026-10-13 `946e01b9`와 화면 `fe536d042635`를 홈서버에 설치했다. 기존 파일은 `release-backups/before-terminal-946e01b9.tgz`에 보관했다. /home/codex tmpfs를 추가한 aiqa-terminal 컨테이너 생성과 aiqa 재시작 명령이 완료됐다. 타입·린트·테스트 및 브라우저 동작 검증은 실행하지 않았다. 기존 화면은 한 번 새로고침해야 새 코드가 적용된다.

2026-10-13 후속 수정: 운영 Codex가 필수로 요구하는 supports_parallel_tool_calls를 카탈로그에 false로 명시한다. 게이트웨이는 동작을 순서대로 실행하며 AI 설정 모델은 변경하지 않는다.

터미널 제목·연결 상태·재연결·접기 버튼은 단일 패널 헤더에 함께 표시한다. 별도 상태 행은 제거한다.

2026-10-13 터미널 팁 숨김: 생성하는 Codex 설정에 `[tui] show_tooltips = false`를 지정한다. 새 터미널 연결부터 시작 팁을 표시하지 않는다.

## 대화 보존 (2026-10-13)

연결 종료 시 HOME을 삭제하던 규칙을 폐기한다. 재실행 parent 체인의 첫 실행 ID를 대화 키로 사용하고, 전용 aiqa-codex 볼륨의 /home/codex/<ID>에 Codex 기록을 보관한다. 재연결·새로고침은 같은 HOME에서 `codex resume --last`로 대화를 복원한다. 연결마다 모델 설정과 임시 게이트웨이 토큰은 갱신하며 실제 API 키는 계속 master에만 둔다. 연결이 끊기면 프로세스는 종료하지만 대화 파일은 남는다. 이전 임시 HOME에서 이미 삭제된 대화는 복원할 수 없다. 모델 설명은 마침표 없는 `기본모델`이다.

2026-10-13 실행 화면 높이: `100dvh - 12rem` 고정 계산을 제거하고 main → 탭 → 실행 패널을 flex 잔여 높이로 연결한다. 제목 높이와 관계없이 하단 터미널이 main의 끝까지 채우며 기존 높이 조절·접기 기능을 유지한다.
